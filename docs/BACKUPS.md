## Новая ротация

- Каталог: `/var/backups/agm-site`, root:root, 0700; содержимое создаётся с umask 0077, веб-пользователь не может прочитать копии.
- Скрипт: `/usr/local/sbin/agm-site-backup`; исходник в `infra/agm-site-backup.py`.
- `agm-site-backup.timer` включён. Ежедневно 00:00 UTC с задержкой до 10 минут, то есть 03:00–03:10 Europe/Moscow. Первый следующий запуск при настройке: 2026-09-22 00:06:42 UTC.
- `Persistent=true`: пропущенный запуск выполняется после включения ВМ. Это серверное расписание, не зависит от включённого рабочего компьютера/Codex.
- Хранятся **3 последних успешных полных комплекта**. Пока создан первый, следующие заполнят оставшиеся места. Первый комплект занимает около 1,4 ГиБ; при том же размере ещё два займут примерно 2,8 ГиБ.
- В каждом комплекте: `site.tar.gz` (полный `/srv/agm/site`, включая медиа и закрытую конфигурацию), `database.sql.gz`, `config.tar.gz` (Apache, PHP, MySQL, dev-TLS и конфигурация механизма бэкапа), `manifest.json`, `SHA256SUMS`.
- Дамп создаётся через root socket, без пароля в аргументах; `--single-transaction --quick --routines --events --triggers --no-tablespaces --set-gtid-purged=OFF`. Проверяется, что базовые таблицы InnoDB и защитные dev-флаги включены.
- Сначала создаётся временный комплект, проверяются gzip, читаемость tar, завершение дампа и SHA-256. Готовый комплект публикуется атомарным переименованием. Только затем удаляются старые сверх лимита; перед удалением перепроверяются хэши сохраняемых копий.
- При ошибке или нехватке места старые исправные копии не вытесняются. Перед стартом требуется место под несжатые файлы сайта, оценку БД и ещё 2 ГиБ резерва. Блокировка исключает параллельные запуски. Незавершённый вывод удаляется при штатной ошибке; после аварийного завершения — при следующем запуске.

Не создавать больше бесконечные каталоги pre-* перед каждой правкой. Для новой точки восстановления запускать этот же сервис и дождаться подтверждённого успеха. Не запускать изменения схемы БД или файлов одновременно с бэкапом: транзакционный SQL-снимок и архив файлов не являются единым атомарным снимком ВМ.

## Управление

```sh
sudo systemctl start agm-site-backup.service
sudo systemctl show agm-site-backup.service -p Result -p ExecMainStatus
systemctl list-timers agm-site-backup.timer --all
sudo journalctl -u agm-site-backup.service -n 20 --no-pager
sudo du -sh /var/backups/agm-site
df -h /
```

Результат успешного oneshot: `Result=success`, `ExecMainStatus=0`, сервис после завершения не обязан оставаться active. Ручной `start` ожидает завершения. Не прерывать его ради тайм-аута клиентского инструмента; можно запускать `--no-block` и отдельно проверять результат.

Для установки на восстановленной dev-ВМ: `install -m 755 infra/agm-site-backup.py /usr/local/sbin/agm-site-backup`, скопировать два unit-файла в `/etc/systemd/system`, создать root-каталог `/var/backups/agm-site` с 0700, выполнить `systemctl daemon-reload`, проверить первый запуск и затем `systemctl enable --now agm-site-backup.timer`. Пути и socket-аутентификацию MySQL проверить до установки.
