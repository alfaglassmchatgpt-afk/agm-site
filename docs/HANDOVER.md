# Продолжение работы с другого компьютера

## Если ВМ сохранилась

1. Клонировать https://github.com/alfaglassmchatgpt-afk/agm-site.git. Прочитать AGENTS.md и STATUS.md.
2. Установить Git и OpenSSH. Получить профиль WireGuard и разрешённый SSH-доступ у владельца через защищённый канал. Их нет в GitHub. Предпочтительно отдельный ключ нового компьютера; не восстанавливать приватные ключи из истории чата.
3. Подключить WireGuard. Сверить SSH host key с доверенным источником владельца. Выполнить `ssh -o BatchMode=yes kirill@192.168.1.58`. Не отключать проверку host key.
4. Проверить `df -h /` и `sudo -n true`. Рабочая директория WordPress: `/srv/agm/site`.
5. Убедиться в dev-флагах: `sudo -u www-data wp --path=/srv/agm/site --skip-plugins --skip-themes config get AGM_STAGING` и аналогично DISABLE_WP_CRON. Ожидается 1.
6. Сверить сертификат с ВМ: `sudo openssl x509 -in /etc/ssl/agm-staging/server.crt -noout -fingerprint -sha256 -dates -ext subjectAltName`. Сравнить с INVENTORY.md. На Windows можно импортировать проверенный certificates/agm-dev.crt командой `Import-Certificate -FilePath certificates/agm-dev.crt -CertStoreLocation Cert:\CurrentUser\Root`. Эта операция действует только для текущего пользователя этого компьютера.
7. Открыть https://192.168.1.58/. Вход WordPress получить отдельно у владельца. Не сбрасывать пароль автоматически.
8. До изменения сравнить выбранные файлы с актуальной ВМ: src содержит очищенные данные и исключения. Сохранять отдельную защищённую копию изменяемых оригиналов вне публичного репозитория. Вносить и проверять изменения только на dev.
9. После работы обновить журнал, инвентаризацию при необходимости и безопасный код в GitHub. Проверить, что новый коммит доступен удалённо.

## Если ВМ потеряна

Одного этого репозитория недостаточно для восстановления всего сайта. Нужны отдельные защищённые резервные копии:

- SQL-база, включая Elementor/ACF, настройки, записи и медиа-метаданные;
- wp-content/uploads и полные темы с исключёнными ресурсами;
- коммерческие/сторонние плагины нужных версий и права на их использование;
- локальные wp-content/agm-vendor и другие необходимые ресурсы;
- закрытая конфигурация сервера/WordPress и материалы WireGuard, доступные только владельцу.

Наличие внешней защищённой резервной копии и пробное восстановление на дату инвентаризации **не подтверждены**. Каталог /srv/agm/source находится на том же диске и не защищает от потери ВМ.

Перед восстановлением создать изолированную ВМ, подготовить Apache/PHP/MySQL совместимых версий, восстановить закрытые данные, задать dev-конфигурацию и применить защитные MU-плагины/Apache **до первого веб-запуска WordPress**. Не запускать WP-CLI с боевыми интеграциями. Замены URL в сериализованных данных делать средствами WP-CLI с предварительным dry-run и бэкапом; SQL replace может повредить Elementor/ACF. После этого проверить ресурсы, авторизацию, редактор и блокировку отправок. Восстановление в этой задаче не выполнялось.

## Резервное копирование

Договориться с владельцем о защищённом внешнем хранилище, шифровании, сроках хранения и восстановлении ключей. Не складывать дампы в репозиторий даже в приватную ветку. При почти полном диске передавать данные потоком во внешнее защищённое хранилище или сначала расширить диск. Проверить пробное восстановление, а не только наличие архива. Автоматический бэкап БД/медиа пока не настроен.
