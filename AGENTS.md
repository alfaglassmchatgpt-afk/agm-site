# Правила работы с проектом

1. Сначала прочитать README.md, docs/STATUS.md, docs/HANDOVER.md и последний журнал изменений. Проверить git status и актуальность origin/main.
2. По решению владельца от 2026-10-21 прежняя dev-ВМ выведена из рабочего процесса: не подключаться к ней и не требовать её доступности. Конфигуратор разрабатывается и проверяется локально; для других задач среду согласовывать отдельно. Боевой сайт нельзя изменять или подключать к dev-интеграциям без отдельного задания владельца.
3. Публичный репозиторий. Не добавлять wp-config.php, .env, ключи, токены, пароли, WireGuard-конфигурации, БД, дампы, логи, заявки, данные пользователей, фотографии/имена сотрудников или клиентские файлы. Не выводить секреты в ответы или журналы инструментов.
4. src — очищенный неполный снимок. Исключённые файлы перечислены в docs/source-exclusions.json; бинарные медиа исключены ещё при получении. Не разворачивать этот снимок поверх сайта целиком. Рабочие изменения переносить выборочно, после сравнения с актуальными файлами целевой среды.
5. Сохранять AGM_STAGING, DISABLE_WP_CRON, защитные MU-плагины, CSP, запрет почты/внешних запросов и публичных записей. Не включать плагины интеграций ради удобства тестирования.
6. Перед изменением проверить свободное место и docs/BACKUPS.md. Сведения о месте и сервисе резервирования прежней dev-ВМ являются архивными; этот сервис больше не запускать. Резервирование выбирать для действующей целевой среды; не создавать неограниченные архивы pre-*. Не удалять сохранённые исторические копии вне настроенной ротации без согласования.
7. После каждого значимого изменения обновить STATUS.md и CHANGELOG.md, при изменении окружения также INVENTORY.md и components.json. Проверить содержимое всего коммита на секреты/персональные данные, затем сохранить код и сведения в GitHub. Сам .gitignore не является проверкой безопасности.
8. Не делать force push и не переписывать историю. Для новых изменений использовать ветки codex/. Для PR описать результат и проверки. Не включать автоматическое развертывание на production.
9. Перед публикацией запускать scripts/check-public-content.ps1 и вручную просматривать diff. Regex-проверка не доказывает отсутствие персональных данных.
10. Если изменились только БД/контент, записать безопасное описание изменений и необходимость защищённого бэкапа; не публиковать выгрузку этих данных.
11. Стандартный конфигуратор проекта называется «Мой расчёт». При создании любой карточки товара (материала или изделия) подключать существующий общий конфигуратор по умолчанию; исключать только по явному указанию владельца. Не создавать отдельные копии логики. Возможности брать из профиля конкретного материала: неподтверждённые специальные обработки не включать, классические зеркала не закаливать, размеры задавать целыми миллиметрами с шагом 1 мм. Правила и исключения: docs/CONFIGURATOR.md.
